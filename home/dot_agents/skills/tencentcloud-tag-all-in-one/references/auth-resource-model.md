# CAM、标签鉴权与资源模型

## 资源身份

标签绑定的对象不是裸 `resourceId`，而是资源六段式表示的完整资源身份。常见差异维度包括 `serviceType`、region、账号主体、`resourcePrefix` 和 `resourceId`。仅凭资源 ID 相同不能断言是同一绑定记录。

历史或特殊产品可能不遵循通用写法。COS 桶存在特殊账号/资源 ID 组合，不同 API 的兼容形式也不同；TKE/CCS 等特殊类型应读取 `4016653046`，不要套用普通六段式猜测参数。

## CAM 前提

标签资源级鉴权依赖以下条件同时成立：

- 查询和操作 Action 在 CAM 中是资源级，而非操作级或服务级。
- CAM 与标签配置中的资源前缀一致。
- 标签控制台登记了正确的资源查询列表 API，且该 API 在 CAM 中存在。
- 查询 API 返回的资源身份和标签绑定使用同一套语义。

缺失查询 API 会让标签控制台无法展示资源，也让平台无法判断标签鉴权能力；前缀不一致会导致鉴权不生效。

## 调用身份

控制台 SDK 通常以当前登录用户临时凭证调用。后端包装标签能力时，应按当前内部规范使用能代表请求方的临时身份并遵守最小权限。服务角色方案权限面较大，只适用于有明确理由的特殊场景。删除资源与解绑标签权限不一致时，不能简单忽略解绑失败，否则会制造脏数据；具体身份方案必须读取 `4008495681` 的当前版本。

## 项目兼容

历史项目管理与标签共存：`ProjectId > 1` 表示历史项目数据，`ProjectId = -1` 表示普通标签语义；`project` 及相关系统保留键存在特殊限制。项目数量、白名单和 2025 年后的兼容规则会变化，查询时读取 `4016222015`。历史 `project` 标签因前端校验无法解绑时，知识入口是 `4008495684`。
