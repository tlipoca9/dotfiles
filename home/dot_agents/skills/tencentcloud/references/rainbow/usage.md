# 使用与配置建模

## 选型

七彩石适合带版本、审批、灰度、回滚和实时下发的业务配置。它不是服务发现/协调系统（不要按 ZooKeeper/ETCD 使用），也不是代码/大文件版本库（不要按 Git/SVN 使用）。

## 标准接入顺序

1. 从“服务地址”页按集群和网络选择控制台及接入点。
2. 创建项目，记录 appid；规划环境、角色和权限。
3. 以服务/应用粒度建分组，选择配置类型。
4. 写配置，执行格式与业务校验。
5. 接入官方 SDK/Agent，启用缓存并预加载。
6. 提交发布任务：看 DIFF、选择审批、设置灰度步骤。
7. 灰度观察客户端版本状态和业务指标，再全量；异常立即回滚。

## 配置类型

- **KV**：短字符串、JSON、XML/YAML 等 UTF-8 文本；SDK 缓存在内存。
- **文件**：Excel、图片、视频、二进制等，底层为 COS；优先 rainbow-agent 落盘，或使用支持文件拉取的 SDK。
- **Table**：多行多列结构，支持数字、文本、结构化文本、枚举、时间、颜色、bool、URL 等字段。
- **模板化配置**：把跨环境/地域共性放模板、差异放变量，适合复杂配置复用和跨环境流转。
- **多 SET**：同一环境按 SET/地域/Region 选择配置；客户端必须正确上报 SET，且应设计默认 SET。
- **特性开关/填色板/ConfigMap/GitOps/智研模板**：场景化能力，先确认客户端和集群支持矩阵。

## 当前规范快照（最终以源文档为准）

主集群文档记录：每项目每环境最多 5000 分组；KV 最多 3000 条；string value 最大 256KB；number 最多 64 位数字。文档不同年代出现过不一致的文件/KV尺寸描述，**禁止引用旧表格定案**，必须回源：

```bash
iwiki-cli get 4008493705   # 配置使用规范
iwiki-cli get 4013716361   # 发布额度
iwiki-cli get 4008546665   # 调用额度
iwiki-cli get 46339995     # 服务地址
```

## 发布模型

发布本质是服务端维护“客户端标签 → 新/旧版本”的匹配规则。无任务时返回上次发布版本；灰度时命中已执行规则的实例取新版本，其余取旧版本；全量后均取新版本。

审批插件包括通用、免审批、Review、智研等；会签要求所有人通过，或签任一人通过。灰度可按 IP/dockerid/自定义标签，用 `IN` 或 `MATCH`，也可动态按实例数/百分比选择。发布不会自动推进，需页面或接口执行。

状态：待审批 → 待发布/已回滚 → 已灰度 → 已全量 → 已完成。已完成不可再操作；历史发布仅保证保留最近 30 个版本记录。完整说明：[发布配置](https://iwiki.woa.com/p/1857645313)。
