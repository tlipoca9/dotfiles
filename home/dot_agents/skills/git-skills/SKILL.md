# Git and GitHub skills

Each **sub-skill** lives in `references/<name>/` with its entry point at `references/<name>/INSTRUCTIONS.md`. Two kinds:

- **Vendored**: an upstream skill copied whole, named `<owner>-<repo>-<skill>` after its source, its upstream `SKILL.md` renamed to `INSTRUCTIONS.md` so harnesses load only this router, its license beside it as `LICENSE`.
- **Local**: hand-written here, listed under `local` in `sources.json`, with no upstream.

## Running a sub-skill

1. Pick every sub-skill below whose trigger matches the task.
2. Read its `INSTRUCTIONS.md` in full and follow it. Links and paths inside resolve from that file's folder; `<skill-dir>` means this router's folder.
3. Done when the sub-skill's own completion criterion is met.

| Sub-skill | Kind | Reach for it when |
|---|---|---|
| [`mitsuhiko-agent-stuff-commit`](references/mitsuhiko-agent-stuff-commit/INSTRUCTIONS.md) | Vendored | Before making any git commit |
| [`mitsuhiko-agent-stuff-update-changelog`](references/mitsuhiko-agent-stuff-update-changelog/INSTRUCTIONS.md) | Vendored | Before updating a changelog |
| [`mitsuhiko-agent-stuff-github`](references/mitsuhiko-agent-stuff-github/INSTRUCTIONS.md) | Vendored | Working with GitHub issues, PRs, CI runs, or the API through `gh` |
| [`git-repos`](references/git-repos/INSTRUCTIONS.md) | Local | Reading, analyzing, or citing a remote repository's source: clone it under `./.local/<host>/<path>/` |

## Updating

`sources.json` lists the upstream repos and skill folders to vendor, with `"prefix": true` so sub-skill names carry their repo, plus the `local` sub-skills; `upstream.lock.json` pins upstream commits. Vendored `references/<name>/`, `scripts/<name>/` and the lock are generated by `scripts/update.py`; keep hand edits to this file, `sources.json`, the script, and local sub-skills. Run from this skill's folder:

1. `uv run scripts/update.py --check`: exit 0 means up to date; exit 1 means an upstream moved.
2. `uv run scripts/update.py` syncs every source to its `ref` (set a branch, tag, or commit in `sources.json` to pin one), leaving local sub-skills untouched. It prints each source's old and new commit plus added or removed sub-skills with their descriptions.
3. Exit 2 means the routing table above disagrees with the sub-skills. Add a row for each added sub-skill, delete rows for removed ones, then repeat `uv run scripts/update.py --lint` until it exits 0.

To add a vendored sub-skill, append its folder to a source's `skills` in `sources.json` (or add a source with `"prefix": true`), then run step 2. To add a local one, write `references/<name>/INSTRUCTIONS.md`, list `<name>` under `local`, and add its row.
