# Frontend skills

Each **sub-skill** is an upstream skill vendored whole into `references/<name>/`, named `<owner>-<repo>-<skill>` after its source. Its entry point is `references/<name>/INSTRUCTIONS.md` (upstream's `SKILL.md`, renamed so harnesses load only this router). Its upstream license sits beside it as `LICENSE`; its scripts live in `scripts/<name>/` and its templates in `assets/<name>/`.

## Running a sub-skill

1. Pick every sub-skill below whose trigger matches the task.
2. Read its `INSTRUCTIONS.md` in full and follow it. Links and paths inside resolve from that file's folder; `<skill-dir>` means this router's folder.
3. Done when the sub-skill's own completion criterion is met.

| Sub-skill | Reach for it when |
|---|---|
| [`edisonmbli-refactoring-ui-skill-refactoring-ui`](references/edisonmbli-refactoring-ui-skill-refactoring-ui/INSTRUCTIONS.md) | Any visual UI work: new pages or components, refining UI that looks off, design reviews, design tokens; rules from the book *Refactoring UI* with Tailwind mappings |

## Updating

`sources.json` lists the upstream repos and skill folders to vendor, with `"prefix": true` so sub-skill names carry their repo; `upstream.lock.json` pins their commits. `references/`, `scripts/<sub-skill>/`, `assets/<sub-skill>/` and the lock are generated by `scripts/update.py`; keep hand edits to this file, `sources.json`, and the script. Run from this skill's folder:

1. `uv run scripts/update.py --check`: exit 0 means up to date; exit 1 means an upstream moved.
2. `uv run scripts/update.py` syncs every source to its `ref` (set a branch, tag, or commit in `sources.json` to pin one). It prints each source's old and new commit plus added or removed sub-skills with their descriptions.
3. Exit 2 means the routing table above disagrees with the vendored sub-skills. Add a row for each added sub-skill, delete rows for removed ones, then repeat `uv run scripts/update.py --lint` until it exits 0.

To add a sub-skill, append its folder to a source's `skills` in `sources.json` (or add a source with `"prefix": true`), then run step 2.
