# Writing skills

Each **sub-skill** lives in `references/<name>/` with its entry point at `references/<name>/INSTRUCTIONS.md`. Two kinds:

- **Vendored**: an upstream skill copied whole, named `<owner>-<repo>` after its source, its upstream `SKILL.md` renamed to `INSTRUCTIONS.md` so harnesses load only this router, its license beside it as `LICENSE`.
- **Local**: hand-written here, listed under `local` in `sources.json`, with no upstream.

## Running a sub-skill

1. Writing anything a person reads: run `technical-writing`. It calls a humanizer for the review pass of long documents.
2. Reviewing or rewriting existing prose for AI tells: run the humanizer for the text's language, keeping technical text in a neutral register as `technical-writing` describes.
3. Read the chosen `INSTRUCTIONS.md` in full and follow it. Links and paths inside resolve from that file's folder; `<skill-dir>` means this router's folder.
4. Done when the sub-skill's own completion criterion is met.

| Sub-skill | Kind | Reach for it when |
|---|---|---|
| [`technical-writing`](references/technical-writing/INSTRUCTIONS.md) | Local | Writing or editing reports, tickets, docs, API descriptions, comments, PR bodies, or long replies |
| [`blader-humanizer`](references/blader-humanizer/INSTRUCTIONS.md) | Vendored | Reviewing English prose for AI writing patterns |
| [`jiji262-humanizer-chinese`](references/jiji262-humanizer-chinese/INSTRUCTIONS.md) | Vendored | Reviewing Chinese prose for AI writing patterns |

## Updating

`sources.json` lists the upstream repos, each vendoring its root skill (`"."`) with `"prefix": true`, plus the `local` sub-skills; `upstream.lock.json` pins upstream commits. Vendored `references/<name>/`, `scripts/<name>/` and the lock are generated by `scripts/update.py`; keep hand edits to this file, `sources.json`, the script, and local sub-skills. Run from this skill's folder:

1. `uv run scripts/update.py --check`: exit 0 means up to date; exit 1 means an upstream moved.
2. `uv run scripts/update.py` syncs every source to its `ref` (set a branch, tag, or commit in `sources.json` to pin one), leaving local sub-skills untouched. It prints each source's old and new commit plus added or removed sub-skills with their descriptions.
3. Exit 2 means the routing table above disagrees with the sub-skills. Add a row for each added sub-skill, delete rows for removed ones, then repeat `uv run scripts/update.py --lint` until it exits 0.

To add a local sub-skill, write `references/<name>/INSTRUCTIONS.md`, list `<name>` under `local`, and add its row. New examples from the user's corrections go in `references/technical-writing/examples.md`; new lint patterns go in `scripts/technical-writing/lint.py`.
