# 七彩石自身开发与测试

此分支面向维护 Rainbow 平台、SDK、Agent、插件和接口的开发者，不适用于普通业务接入。

## 先定位边界

- 管理面：项目/环境/分组、版本、任务、审批、权限、操作记录。
- 数据面：Pull/Get、长轮询、标签匹配、缓存与版本计算。
- 客户端：SDK/Agent 的发现、签名、预加载、内存/文件缓存、Watch、文件下载。
- 扩展面：审批、数据过滤、发布编排、ConfigMap、GitOps 等插件。

## 改动清单

1. 先读 [架构设计](https://iwiki.woa.com/p/40649681)、[对外协议](https://iwiki.woa.com/p/17511161)、[数据库设计](https://iwiki.woa.com/p/40644746) 和目标模块设计。
2. 明确兼容性：老客户端、老协议字段、默认值、单/多集群、灰度中的旧版本、缓存文件格式。
3. 为状态机定义合法迁移、幂等键、并发冲突、失败补偿和回滚。
4. 为缓存/消息链路验证顺序性：DB 真相源、服务缓存、通知、客户端长轮询与本地缓存不得出现版本倒退。
5. 新错误使用所属区段且保持旧语义；同步 API 文档、SDK 映射、监控和排障说明。
6. 测试至少覆盖：权限、参数边界、并发、限流、超时、依赖故障、灰度命中/未命中、回滚、缓存恢复、多集群和老版本 SDK。
7. 压测区分管理面和读取面；给出吞吐、P99、错误率、资源水位和降级结果。

## 设计护栏

- 配置读取链路优先可用性；客户端缓存必须能隔离服务端故障。
- 发布和回滚必须幂等，禁止并发任务导致版本规则互相覆盖。
- 长轮询超时/无版本变化是协议正常路径，不应制造错误风暴。
- SDK 更新缓存时拒绝旧版本覆盖新版本；文件缓存写入需原子化并考虑加密、权限和污染修复。
- 插件失败不能悄悄绕过审批、过滤或发布约束。
- 多集群方案必须定义数据复制方向、服务发现、发布一致性、逃生切换和回切。
