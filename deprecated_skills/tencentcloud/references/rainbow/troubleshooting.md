# 排障与坑点

## 最短诊断链

1. 固定证据：时间、集群/网络、appid/env/group、配置类型、目标版本、客户端语言/版本/IP/标签、请求或任务 ID、完整错误码和日志。
2. 控制台确认项目/环境/分组存在，至少有一个已发布版本，任务状态和灰度规则符合预期。
3. 确认客户端使用正确接入点、权限/签名、缓存、预加载和标签。
4. 比较同分组正常与异常实例；用 DNS、连接、超时、服务发现、COS 分层探测，不直接绕过 SDK 作为“修复”。
5. 对照 [错误码](https://iwiki.woa.com/p/46362618) 和语言 SDK 源码；若疑似服务端，携带证据升级。

## 高频协议码

- `100` 权限/签名；`102` 未申请公网访问。
- `200` 参数错误；`201` API 版本不匹配；`203` 客户端主动断链。
- `600/601/602` RPC、超时或报文解析；`604` 请求过频。
- `702` 版本无变化，常为正常状态；灰度未命中也可能出现。
- `704` 空版本；`706` key 不存在；`707` 无版本/项目或分组删除/尚未发布。
- `708` 长轮询超时，应按协议再次请求；`719` 公共分组不能直接拉取。
- Admin `1021` 表示当前任务无可回滚版本；回滚仅适用于合法的全量/灰度状态。
- C++ `-6` 常见为 DNS 解析失败，先测 `time_namelookup`；`28` 为请求超时。

## 典型坑

- **配置未生效**：改了但未发布；实例未命中灰度标签；连错集群/env/group；Watch 正常但回调失败；旧 SDK；缓存目录不可写；客户端版本上报缺失。
- **启动偶发失败**：未预加载、首次业务请求穿透；把服务端短暂异常当硬依赖；没有文件缓存兜底。
- **请求暴涨/604**：关闭缓存、每请求 Get、无延迟轮询 707、重复 Watch/SDK 实例、重试无退避。
- **多 SET 重复/空数据**：标签缺失；多个自定义 SET 同时匹配同 key；变量类型冲突；缺默认 SET。
- **文件失败**：自行访问 COS、网络模式错误、路径权限、部分下载、旧 Agent/SDK。
- **发布/回滚失败**：已有任务进行中、状态不允许、步骤已执行、没有目标实例、审批插件约束、并发任务。
- **fork/多进程异常**：fork 前创建的北极星/SDK 对象在子进程复用；按语言文档在正确进程生命周期初始化。
- **“缓存旧”**：缓存通常永不过期，这是容灾设计；要检查服务端目标版本、通知/长轮询、版本防倒退，而不是先删缓存。

## 回答格式

给出：`最可能原因（按概率） → 每项验证命令/观察点 → 临时止损 → 根治 → 回归验证`。不要建议关闭缓存、提高无限重试或直接调用私有接口来掩盖问题。
