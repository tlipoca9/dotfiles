# 标签异常与脏数据知识

## 先区分数据边界

业务控制台的资源列表来自业务查询 API；标签库保存资源与标签的绑定；标签控制台会组合业务资源查询和标签数据。三处不一致时，先判断缺的是“资源事实”还是“标签绑定事实”。

| 现象 | 首要知识入口 |
| --- | --- |
| 业务控制台不显示标签，但标签后台有正确绑定 | 业务前端或查询接口展示链路；`4010563915` |
| 标签控制台某地域找不到产品 | 核对产品已配置地域；`4012511711` |
| 标签控制台找不到资源 | 核对其调用的资源列表 API、参数映射和业务 API 返回；`4012511711`、`4012527240` |
| 业务控制台看不到资源 | 核对标签授权键值、资源状态和搜索条件；`4009537509` |
| 资源已销毁但仍有标签 | 业务销毁链路未解绑或解绑失败；`4015928613` |
| CAM 标签鉴权不生效 | 核对授权粒度、查询 API 和两侧 `resourcePrefix`；`4009183068`、`4015537251` |
| 同一资源 ID 有多条记录 | 比较完整六段式；可能是错误前缀，也可能是跨产品双写；`4008495682` |
| 标签键值重复 | 检查历史前后空格或不可见字符；`4008495687` |
| 资源数为 0 仍无法删标签 | 先确认底层是否仍有关联；历史异常可能需标签侧处理；`4008495687` |
| 标签被修改 | 查操作审计或内部事件记录，再识别子用户、角色、主账号或上游系统；`4008495679`、`4012541393` |
| 分账归属错误 | 核对六段式、计费映射与账单侧数据；`4012467628` |

## 稳定诊断知识

- 标签团队的系统作为下游，不会无缘无故主动修改用户标签；变更可能由用户、角色、业务产品或内部治理平台调用 Tag API 产生。
- 查修改来源时，公有云用户优先看操作审计；内部可按 UIN、资源 ID 和时间查询标签事件，再根据操作者类型追到用户、角色、`componentName`、caller 或来源 IP。
- 销毁脏数据的判定必须由标签库记录与业务侧真实资源交叉验证；回收站中的资源不能直接视为已销毁。
- 错误六段式的解绑通常需要沿用当初错误的完整资源身份，否则目标记录匹配不到。
- 历史不合法键值可能含首尾空格、制表符等不可见字符。先识别原值和关联资源，再讨论迁移或删除。
- 云梯等同步系统可能有固有延迟；看见短期不一致不能直接判定 Tag 数据错误。

## 时效提醒

内部查询入口、保留天数、上游特殊逻辑、联系人和处理权限会变化。涉及“现在怎么查”时必须读取 `4008495679`、`4012541393` 及对应现象文档的当前版本。
